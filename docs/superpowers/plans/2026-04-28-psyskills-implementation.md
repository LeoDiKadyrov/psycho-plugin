# psyskills Plugin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Создать Claude Code плагин `psyskills` с четырьмя клиническими скиллами для психолога-практика.

**Architecture:** Модульные независимые скиллы (Вариант Б). Каждый скилл читает/пишет единый `clients/имя.md`. Reference-файлы содержат базу знаний по модальностям (наполняет пользователь). Модальность определяется из frontmatter файла клиента, переопределяется аргументом.

**Tech Stack:** Claude Code Plugin (markdown-based), YAML frontmatter, Markdown.

## Task 4: psy:conceptualize skill

**Files:**
- Create: `skills/conceptualize/SKILL.md`

- [ ] **Step 1: Создать `skills/conceptualize/SKILL.md`**

```markdown
---
name: psy:conceptualize
description: Analyze therapy session transcript and update client conceptualization using Lazarus BASIC ID model. Use when given a session transcript and need to update or refine client conceptualization.
---

Анализируй транскрипт терапевтической сессии и обновляй концептуализацию клиента по модели BASIC ID (Лазарус).

## Входные данные

Аргументы: `/psy:conceptualize <имя-клиента> [путь-к-транскрипту] [модальность]`

- `имя-клиента` — обязательный. Соответствует файлу `clients/<имя-клиента>.md`
- `путь-к-транскрипту` — необязательный. Если не указан — попроси вставить текст транскрипта
- `модальность` — необязательный (`cbt` или `orct`). Если не указан — читай из frontmatter файла клиента

## Процедура

1. **Прочитай файл клиента** `clients/<имя-клиента>.md`. Если файл не существует — создай его из `templates/client-template.md` и попроси заполнить базовые данные перед продолжением.

2. **Определи модальность** — из аргумента или frontmatter. Если не задана нигде — спроси.

3. **Прочитай reference-файлы:**
   - Всегда: `references/lazarus-basic-id.md`
   - По модальности: `references/cbt.md` или `references/orct.md`

4. **Получи транскрипт:**
   - Если путь указан: прочитай файл по этому пути
   - Если нет: выведи сообщение "Вставь текст транскрипта сессии:" и жди ввода

5. **Проведи анализ транскрипта** через призму BASIC ID. Для каждой модальности:
   - Что нового появилось по сравнению с текущей концептуализацией?
   - Что подтверждается или уточняется?
   - Что противоречит текущей концептуализации?

6. **Представь предлагаемые обновления** в структурированном виде:

```
## Предлагаемые обновления концептуализации

### B — Поведение
[новые данные / уточнения / без изменений]

### A — Аффект
...

[и т.д. по всем модальностям]

### Связи между модальностями
[новые выявленные связи]
```

7. **Спроси подтверждение:** "Применить эти обновления к `clients/<имя>.md`? (да / нет / изменить)"

8. **На подтверждении "да":** обнови секцию `## Концептуализация (BASIC ID)` в файле клиента. Добавь запись в `## История сессий`:
```
### [дата]
- Обновлена концептуализация по транскрипту сессии
```

## Важно

- Не перезаписывай существующую концептуализацию полностью — дополняй и уточняй
- Сохраняй датированную историю изменений
- Если reference-файл пустой — работай по базовым знаниям о BASIC ID, но предупреди пользователя
```

```markdown
Уточняй и формализуй терапевтический контракт и цели клиента.

## Входные данные

Аргументы: `/psy:goals <имя-клиента> [путь-к-транскрипту] [модальность]`

2. **Определи модальность** — из аргумента или frontmatter

   - Прочитай транскрипт (из файла или попроси вставить)
   - Извлеки всё, что связано с запросом, целями, пожеланиями, ожиданиями клиента
   - Сравни с текущими зафиксированными целями

5. **Представь анализ:**

```

[что говорил клиент о целях / запросе / ожиданиях]

## Предлагаемая формулировка

### Запрос клиента
[уточнённая формулировка]

### Согласованные цели терапии
1. ...
2. ...

### Критерии достижения
- ...
```

6. **Спроси подтверждение:** "Обновить секцию 'Контракт и цели' в `clients/<имя>.md`?"

7. **На подтверждении:** обнови секцию `## Контракт и цели`. Добавь запись в историю.

## Важно

- В КПТ цели должны быть конкретными, измеримыми, достижимыми (SMART-ориентация)
- В ОРКТ цели формулируются в терминах присутствия желаемого, а не отсутствия проблемы
- Всегда проверяй согласованность целей с концептуализацией
```

## Task 7: psy:supervise skill

**Files:**
- Create: `skills/supervise/SKILL.md`

- [ ] **Step 1: Создать `skills/supervise/SKILL.md`**

```markdown
---
name: psy:supervise
description: Supervise a therapy session by evaluating conceptualization quality, contract/goals, strategy, and therapist performance. Produces a structured report with scores and recommendations.
---

Проводи супервизию терапевтической сессии — оценивай концептуализацию, контракт/цели, стратегию и работу терапевта.

## Входные данные

Аргументы: `/psy:supervise <имя-клиента> [путь-к-транскрипту] [модальность]`

- `имя-клиента` — обязательный
- `путь-к-транскрипту` — необязательный. Если не указан — попроси вставить текст
- `модальность` — необязательный

## Процедура

1. **Прочитай файл клиента** `clients/<имя-клиента>.md`

2. **Определи модальность**

3. **Прочитай оба reference-файла:**
   - `references/lazarus-basic-id.md`
   - `references/<модальность>.md`

4. **Получи транскрипт** (из файла или попроси вставить)

5. **Проведи оценку по четырём осям:**

### Ось 1: Концептуализация (0–10)
Критерии:
- Полнота охвата всех модальностей BASIC ID
- Внутренняя согласованность
- Связь между модальностями
- Подкреплённость клиническими данными
- Соответствие теоретической модели (КПТ/ОРКТ)

### Ось 2: Контракт и цели (0–10)
Критерии:
- Чёткость формулировки запроса
- Конкретность и измеримость целей
- Согласованность между клиентом и терапевтом
- В КПТ: SMART-формулировки; в ОРКТ: цели в позитивных терминах
- Связь целей с концептуализацией

### Ось 3: Стратегия (0–10)
Критерии:
- Соответствие стратегии концептуализации
- Обоснованность выбора интервенций
- Реалистичность плана
- Гибкость (учтены возможные сложности)

### Ось 4: Работа терапевта в сессии (0–10)
Критерии:
- Следование структуре сессии (по модальности)
- Качество терапевтического альянса (по транскрипту)
- Точность и уместность интервенций
- Работа с сопротивлением/трудностями
- Соответствие подходу (КПТ/ОРКТ)

6. **Выдай структурированный отчёт:**

```
## Супервизия — [имя клиента] — [дата]

### Концептуализация: [X]/10
[3-5 предложений: что хорошо, что можно улучшить, конкретные рекомендации]

### Контракт и цели: [X]/10
[3-5 предложений]

### Стратегия: [X]/10
[3-5 предложений]

### Работа терапевта: [X]/10
[3-5 предложений: конкретные примеры из транскрипта]

### Итого: [сумма]/40

### Приоритетные рекомендации
1. [самое важное для развития]
2. ...
3. ...
```

7. **Спроси:** "Сохранить отчёт в историю сессий `clients/<имя>.md`?"

8. **На подтверждении:** добавь полный отчёт в секцию `## История сессий`.

## Важно

- Оценки должны быть обоснованы конкретными примерами из транскрипта или client.md
- Тон: поддерживающий и конструктивный — это супервизия, не критика
- Если reference-файл пустой — оценивай по базовым знаниям о подходе, предупреди об этом
- Выделяй сильные стороны наравне со зонами роста
```
