---
name: psy:conceptualize
description: Analyze therapy session transcript and update client conceptualization using Lazarus BASIC ID model. Use when given a session transcript and need to update or refine client conceptualization.
---

Анализируй транскрипт терапевтической сессии и обновляй концептуализацию клиента по модели BASIC ID (Лазарус). Используй фреймворк школы: Жалоба → Проблема → Запрос → BASIC ID → Связи.

## Входные данные

Аргументы: `/psy:conceptualize <имя-клиента> [путь-к-транскрипту] [модальность]`

- `имя-клиента` — обязательный. Соответствует файлу `clients/<имя-клиента>.md`
- `путь-к-транскрипту` — необязательный. Если не указан — попроси вставить текст транскрипта
- `модальность` — необязательный (`cbt` или `orct`). Если не указан — читай из frontmatter файла клиента

## Процедура

1. **Прочитай файл клиента** `clients/<имя-клиента>.md`. Если файл не существует — создай его из `templates/client-template.md` и попроси заполнить базовые данные перед продолжением.

2. **Определи модальность** — из аргумента или frontmatter. Если не задана нигде — спроси.

3. **Прочитай reference-файлы:**
   - Всегда: `references/lazarus-basic-id.md`
   - По модальности: `references/cbt.md` или `references/orct.md`

4. **Получи транскрипт:**
   - Если путь указан: прочитай файл по этому пути
   - Если нет: выведи сообщение "Вставь текст транскрипта сессии:" и жди ввода

5. **Проведи анализ транскрипта** по схеме Жалоба → Проблема → BASIC ID:

   **Шаг А — Жалоба** (если первичная сессия или жалоба не зафиксирована):
   - Неудовлетворённость: что именно не устраивает клиента?
   - Несостоятельность: в чём клиент не может справиться сам?

   **Шаг Б — BASIC ID** по конкретным ситуациям из транскрипта:
   - B: что делает / не делает / избегает?
   - A: какие эмоции, их интенсивность, триггеры?
   - S: телесные ощущения?
   - I: образы, метафоры, воспоминания?
   - C: автоматические мысли, убеждения (до / во время / после)?
   - I: кто участвует, как влияет?
   - D: медикаменты, сон, здоровье?

   **Шаг В — Связи между модальностями:**
   Какие модальности запускают друг друга? Построй цепочку (например: мысль → эмоция → поведение → последствия).

   **Шаг Г — Дополнительная информация** (если новые данные появились):
   - Триггеры, исключения, ресурсы, уязвимости, мотивация, детский опыт

   Для каждой модальности: что нового? что подтверждается? что противоречит текущей концептуализации?

6. **Представь предлагаемые обновления:**

```
## Предлагаемые обновления концептуализации

### Жалоба (если обновилась)
[неудовлетворённость + несостоятельность]

### BASIC ID

#### B — Поведение
[новые данные / уточнения / без изменений]

#### A — Аффект
...

#### S — Ощущения
...

#### I — Образы
...

#### C — Когниции
...

#### I — Межличностные
...

#### D — Биология
...

### Связи между модальностями
[новые / уточнённые цепочки]

### Дополнительная информация
[триггеры, исключения, ресурсы, уязвимости — если появились новые]

### Возможная формулировка проблемы
[1-3 варианта в формате: "Трудность с...", "Недостаток...", "Неспособность..."]
```

7. **Спроси подтверждение:** "Применить эти обновления к `clients/<имя>.md`? (да / нет / изменить)"

8. **На подтверждении "да":** обнови секцию `## Концептуализация (BASIC ID)` в файле клиента. Добавь запись в `## История сессий`:
```
### [дата]
- Обновлена концептуализация по транскрипту сессии
```

## Важно

- Не перезаписывай существующую концептуализацию полностью — дополняй и уточняй
- Записывай только те модальности, которые относятся к проблемной ситуации
- Не все модальности будут заполнены за одну сессию — это нормально
- Рассматривай конкретные ситуации из транскрипта, не абстрактные описания
- Если клиент говорит «я чувствую» — проверь: это эмоция (A) или мысль/образ (C/I)?
- Если клиент говорит о нескольких проблемах — отметь все, но работай с той, что сейчас мешает больше всего
- Концептуализация не статична — она дополняется по мере работы
